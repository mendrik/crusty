# Quality learning is reviewable validation memory

Crusty stores reported problems, reusable quality constraints, and per-change validation obligations as separate records in its existing repository-scoped SQLite memory. Explicit defect reports are captured during normal repository work without a separate bookkeeping request, while feature requests and meta-discussion are excluded. Deterministic classification may propose a narrow constraint, but only reviewed constraints activate future validation; historical defects enqueue checks and never silently expand a later change into unrelated implementation work.
